# Estrategia de pruebas de la demo local

> Estrategia de evidencia para la demo local. Cada SPEC concreta las comprobaciones de su incremento antes de implementarlo.

La evidencia de [REL-001 — Demo local operativa de Synqo](../../01_producto/10_entregas/rel-001-demo-local-operativa.md) se centrará en riesgos observables:

| Riesgo | Evidencia mínima |
|---|---|
| Base visual y navegación compartida del primer incremento | Abrir directamente y recargar las rutas simuladas; recorrer creación, confirmación, equipo y pantallas de enlace; comprobar que todas reutilizan el layout exterior y que Calendario y Consultas reutilizan el interior. Verificar temas, teclado, foco y adaptación móvil sobre los elementos presentes, y comprobar que el formulario ilustrativo no crea ni transmite datos. |
| Cálculo de fechas de caducidad, estados diarios, normalización de nombres y opciones | Pruebas de reglas puras con casos límite, incluidas zonas horarias y cambio de mes. |
| Acceso compartido y aislamiento de equipos | Pruebas de integración de API con PostgreSQL: valor válido, ausente, alterado, equipo caducado y borrado; lecturas y escrituras. |
| Persistencia, votos y resolución | Pruebas de integración de operaciones y restricciones, incluyendo dos participantes y consultas abiertas/cerradas. |
| Recorridos esenciales en navegador | Pruebas de extremo a extremo con dos contextos de navegador, desde crear equipo hasta resolver consulta; verificación de recarga y cambio de identidad. |
| Uso móvil y accesibilidad | Recorridos completos responsive con Chromium emulado a 390×844, 768×1024 y 1280×800 CSS px; comprobación del límite 768/769 px. El smoke parcial añade teclado, foco, reflujo y ampliación de texto CSS. Para cada cambio, una ejecución documentada de herramientas automatizadas de accesibilidad satisface el paso automatizado del proceso (herramienta y versión, alcance, resultado e incidencias). Esto no garantiza conformidad ni sustituye la revisión manual. La conformidad con [RNF-COO-002 — Accesibilidad web WCAG 2.2 nivel AA](../../03_requisitos/04_no-funcionales/COO/rnf-coo-002-accesibilidad-web.md) requiere evaluar todos los criterios A/AA aplicables en el alcance acordado; pruebas aisladas no la acreditan. |

El recorrido de [SPEC-COO-004 — Arranque básico en menos de cinco minutos en REL-001](../../08_especificaciones/99_archivadas/spec-coo-004-arranque-cinco-minutos-rel-001.md) permite aceptación automática solo si completa todos los pasos con WEB/API reales en menos de 150 segundos; si tarda 150 s o más, se requiere una ejecución humana del mismo recorrido inferior a cinco minutos. El correo debe terminar sin error; el recibo confirma el resultado del intento, no la entrega en el buzón. La matriz responsive y el alcance del smoke parcial se registran en [SPEC-COO-003 — Uso móvil adaptable en REL-001](../../08_especificaciones/99_archivadas/spec-coo-003-uso-movil-rel-001.md), [SPEC-COO-002 — Smoke de accesibilidad responsive de REL-001](../../08_especificaciones/99_archivadas/spec-coo-002-accesibilidad-wcag-rel-001.md) y [REL-001 — Demo local operativa de Synqo](../../01_producto/10_entregas/rel-001-demo-local-operativa.md). Compilar las piezas o pasar otras pruebas automatizadas no sustituye esas evidencias.
