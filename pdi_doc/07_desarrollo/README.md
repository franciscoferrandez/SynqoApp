# 07 — Desarrollo

## Propósito

Define cómo debe implementarse el software una vez decidida su arquitectura.

## Contiene

convenciones, testing, calidad, Git, CI/CD, DoR/DoD y reglas por módulo.

## No contiene

verdad funcional del producto

## Cuándo se utiliza

Lee esta carpeta cuando la fase o una skill necesite crear, revisar o consultar este tipo de conocimiento.

## Cómo se obtiene

Transforma arquitectura en reglas operables.

## Preguntas que debe realizar el LLM

¿Qué debe respetar cualquier contribución?

## Mandamientos

1. Reglas ejecutables cuando sea posible.
2. Global + específico de módulo.

## Salidas posibles

guías de desarrollo

## Criterios de calidad

- El contenido tiene origen o justificación identificable.
- No duplica una fuente normativa existente.
- Las referencias a artefactos existentes usan `[ID — denominación](ruta/relativa.md)` y apuntan al archivo citado.
- Las incertidumbres relevantes quedan explícitas.
