# OpenSpec — decisión actual

**Estado:** no adoptado en PDI.

Motivo:

1. primero queremos estabilizar el workflow y los gates;
2. las skills actuales son neutrales al proveedor;
3. el Product Baseline ya tiene una ubicación normativa clara en `<DOC>/`;
4. no queremos introducir una segunda fuente de verdad.

## Criterio futuro

OpenSpec podrá evaluarse cuando hayamos ejecutado varios Changes reales y el lifecycle esté estable.

Si se adopta:

```text
OpenSpec / motor similar
→ lifecycle y artefactos temporales del Change

<DOC>/
→ Product Baseline normativo
```

Un schema futuro debería reflejar nuestros pasos, no obligarnos a adaptar el método a un schema por defecto.
